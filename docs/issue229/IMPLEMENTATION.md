# Issue #229 — offline local LoRA library

Manual configured-root recursive `.safetensors` scan, bounded embedded/adjacent JSON metadata and exact-name preview lookup. Ordinary startup performs no scan/hash/network. No downloads, account, Python or external service dependency. Thousands of models use SQL paging (100 rows), a virtualized list and only the selected bounded preview. The 1,000-file cold/warm/query regression passes; a new service/FTS/cache is unnecessary for this baseline.

Separate `UserData/lora-library.db`, schema 1. Schema creation/migration is transactional, existing nonempty older databases are backed up consistently, newer versions refuse. Existing catalog/user.db/Library/research/legacy data are untouched. Every scanned root commits as a unit; an inaccessible root, malformed metadata, changed-during-read file or cancellation rolls back without falsely marking missing. Links/reparse files and directories are excluded.

Full SHA256 is computed for new/changed size/mtime or explicit verification. Unchanged files reuse their hash; changed sidecars refresh independently. Inventory retains separate paths and missing/replaced identities. **Identical SHA256 explicitly means shared personal metadata**, with path-copy counts visible; filename alone never means identity. Renamed identical files recover the same notes. Same basename with different available hashes blocks insertion/preset conversion because Forge's basename resolution would be ambiguous. Before insertion availability/size/mtime/link status is checked. Same-size/time external content replacement requires the explicit hash verification action, as expected with an incremental cache.

User overrides > embedded metadata > adjacent local sidecars. Base-model and individual trigger provenance remain visible; unknown compatibility stays unknown. Preview: explicit local override > exact-name adjacent preview > none. No heuristic family inference. Sidecars support helper-style `baseModel`, `trainedWords`, local source version ID; embedded fields include `modelspec.architecture`, `ss_base_model_version`, `ss_sd_model_name`, `modelspec.trigger_phrase`. ModelSpec phrases are displayed as optional user-selectable triggers, never silently inserted.

User category, favorite, preferred weight, notes, canonical/Character/HOME/Concept/Style relation labels and a small SHA-keyed recipe persist independently. Search matches filename, local facts and personal metadata/relations. Only meaningful LoRA insertion increments count/last-used. Selection does not. Valid and invalid-weight draft text survives selection/search/scan within the session; disk writes require Save. Source files/sidecars are never edited.

Explicit actions: LoRA only, LoRA + selected triggers/Positive recipe, copy triggers, copy Negative additions, existing preset editor. Same existing PromptParser/PromptWorkspace/Undo are used. Negative is an explicit preset/copy step until #232. Weight range -2..2; no block weights. No generation is started by this feature. Optional network enrichment is deferred as allowed by the Issue.
